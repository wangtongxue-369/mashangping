## 1. 背景与问题

后端计划 1-5 已交付一个可独立工作的 Spring Boot 单体（`server/`），覆盖 REST API 与判题流水线，但当前**没有任何前端**（仓库只有 `server/`，无 `frontend/`）。一期路线图 §4 教师端功能多数已有对应后端 API，但有三项**后端端点缺失**：

| 教师端功能（路线图 §4） | 后端现状 |
|---|---|
| 课程 / 学生名单 / 题库 / 测试点 / 作业发布 | ✅ 已有 REST API 复用 |
| 提交记录：查看任意学生的全部历史提交 | ⚠️ 只有学生端 `/api/submissions/my`（`hasRole('STUDENT')`），**缺教师全局视角端点** |
| 成绩册：按作业自动汇总（取最高分） | ❌ **缺后端聚合端点** |
| CSV 导出 | ❌ **缺导出端点** |

阶段 6 补齐这三项后端端点，同时立起一期前端工程与完整教师端控制台，使「内容管理 + 评测结果」两条教师工作流都能在 UI 上闭环。

4. 补齐 3 个后端补端点：成绩册矩阵 / 教师全局提交历史 / CSV 导出

## 4. 共享基建（第一个交付物）

| 组件 | 职责 | 前端 |
|---|---|---|
| `api/client.ts` | axios 实例：`baseURL=/api`；请求拦截器注入 `Authorization: Bearer <token>`；响应拦截器——HTTP 401 → 清 token 重定向 `/login`；HTTP 403 → 明确提示；5xx → 友好提示；**HTTP 200 且 `code≠0`**（业务错误）→ 按 `message` 全局 `message.error` | 教师端全站 |
| `auth/useAuth.ts` | 登录态 React context；`login()` 调 `/api/auth/login`（对齐现有 AuthController）拿 token 存 localStorage；`logout()` 清 token；`useAuth()` 供守卫与请求层取 token | 全站 |
| `layout/ProtectedRoute.tsx` | 无 token → `<Navigate to="/login" />`；有 token 渲染子页面。教师端页面统一包在此守卫下（角色细化由后端 `@PreAuthorize` 强制，前端不复制） | 全站 |
| `api/query.ts` | QueryClient：默认 `staleTime` 适中、读操作 `retry:1`；mutation 提交类不自动重试 | 全站 |

验收：`npm run dev` 起服 → 访问 `/login` 登录 → 拿到 token → 跳 `/teacher/courses` 正常渲染空表格；无 token 直访 `/teacher/*` 被重定向 `/login`。

## 5. 后端补端点（3 个）

遵循项目现有约定：`ApiResponse`（code=0 成功 / 业务错 HTTP200 + code≠0）、`PageUtils` 分页、**教师数据归属链校验**（作业属课 → 课属当前教师，否则越权错误码）,角色 `@PreAuthorize('hasRole(\'TEACHER\')')`。迁移：新增 `V7__gradebook.sql`（如需唯一索引则一并落地，见 §7 遗留）。

### 端点 A · 成绩册矩阵
`GET /api/assignments/{assignmentId}/gradebook`（TEACHER）
- 归属校验：作业属当前教师之课，否则越权。
- 返回结构化矩阵（前端只渲染不聚合）：
  ```json
  {
    "assignmentId": 1, "assignmentTitle": "第1次作业",
    "students":  [ { "studentId": 8, "studentNo": "20240001", "realName": "张三" } ],   // 该课程全部选课学生
    "problems":  [ { "assignmentProblemId": 1, "problemId": 2, "title": "两数之和", "score": 20, "sortOrder": 0 } ],
    "cells":     [ { "studentId": 8, "assignmentProblemId": 1, "bestScore": 20 } ],      // 有有效提交才出现
    "totals":    [ { "studentId": 8, "total": 100 } ]
  }
  ```
- **语义锁定**：`bestScore` = 该生该题全部 submission 中 `status='AC' ? score : 0` 的最高值（对齐判题规约「AC=题分 否则 0」与「同题取最高」）；**无有效提交的学生该题无 cell**（前端渲染 `—`，数学语义为 0）；`total` = 各题 `bestScore`（含 0）之和。**前端不承担聚合逻辑。**
- 实现：按 `assignmentId` 取 `assignment_problem` 列表 + 该课 `enrollment` 学生列表 + 各 (student, ap) 的最高有效分聚合。

### 端点 B · 教师全局提交历史
`GET /api/assignments/{assignmentId}/submissions`（TEACHER）
- 分页参数：`page` / `size`（对齐 PageUtils）；可选筛选：`assignmentProblemId`、`studentId`。
- 返回分页行：`submissionId, studentNo, studentName, problemTitle, language, status, score, passedCount, totalCount, timeUsedMs, memoryUsedMb, submittedAt, isLate`。
- 归属校验同上。`score` 为判题写入的该次提交得分（**非题目最高分**——成绩册才聚合最高分；提交历史是逐条原始记录）。

### 端点 C · CSV 导出
`GET /api/assignments/{assignmentId}/gradebook/csv`（TEACHER）
- 返回 `text/csv` 附件（`Content-Disposition: attachment; filename=gradebook-{assignmentId}.csv`），UTF-8 **含 BOM**（兼容中文 Excel 打开）。
- 语义与端点 A 的矩阵一致：行=学生；列=题目（表头 `题名(分值)`）；末列总分。**未提交 / 未做的格子导出数值 `0`**（锁定语义），与前端展示的 `—` 区分（CSV 中统一为 0）。
- **CSV 注入转义在服务端做**：字段含 `,` / `"` / 换行时按 RFC 4180 引号包裹并双写内引号；前导 `=`/`+`/`-`/`@` 敏感前缀（可导致公式注入）的字段加单引号前缀防御。
- 复用成绩册矩阵的聚合逻辑，避免两处语义漂移。

## 7. 错误处理

| 场景 | 前端策略 |
|---|---|
| HTTP 401 | 清 token → 重定向 `/login`（axios 响应拦截统一处理） |
| HTTP 403 | 明确 message「无访问权限」 |
| HTTP 5xx | 友好提示「服务暂不可用」，不裸抛堆栈 |
| 业务错误（HTTP 200 + `code≠0`） | 全局按 `message` `message.error`，透传后端语义（如 40018/40019/40020/40400） |
| 查询失败（TanStack Query） | 读 `retry:1`；渲染空态/重试按钮 |
| 提交/变更类 mutation | 不自动重试，直接提示错误 |
| 布局级兜底 | 路由懒加载 + `ErrorBoundary` 降级友好页 |

## 8. 权限与可见性边界

- 教师端全部页面挂 `ProtectedRoute`（前端路由守卫：无 token 重定向 `/login`）。
- **数据归属链在后端强制**（补端点校验作业属当前教师之课，越权回越权错误码），前端只做路由级守卫，不复制归属校验 —— 对齐项目既有「权限校验统一放 service 层强制执行」约定。
- 隐藏测试点输入输出永不进入任何响应；样例点 message 教师可见、隐藏点 message 不返回（沿用读侧可见性）。
