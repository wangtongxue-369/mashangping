## 1. 目标与范围

一期 P1 在线评测的核心交付。完成后学生可在作业内或公开题库练习中提交代码，系统经数据库队列调度至一次性 Docker 沙箱完成「编译 → 逐测试点运行比对」，回写终态与逐点明细，并通过 WebSocket 实时推送进度。

**范围包含**：

1. V6 迁移三表：`submission` / `judge_task` / `judge_detail`
2. 提交入口（双入口）+ 九道门校验 + 同题限流
3. 判题调度器（MySQL 队列消费）、崩溃恢复、Docker daemon 故障降级
4. docker-java 一次性沙箱：三镜像、编译→逐点执行→输出比对，覆盖 AC/WA/TLE/MLE/RE/CE 全状态
5. STOMP over WebSocket 判题进度推送
6. 学生读侧接口（提交详情/历史列表）
7. 计划 4 挂账三项清偿（§13）

**范围不含**：教师端提交记录/成绩册/CSV 导出（归收尾批）；Special Judge 实现；gVisor；多机扩展；进程级精确 rusage 计量。

## 2. 已确认决策

| # | 决策 | 结论 |
|---|---|---|
| D1 | 提交入口 | 双入口：作业内题目 + 公开题库练习题；练习不计成绩 |
| D2 | 打分模型 | 整题全对制：全部测试点通过得 `assignment_problem.score` 分，否则 0 分；练习提交 score 恒 NULL |
| D3 | 进度推送 | STOMP over WebSocket（spring-boot-starter-websocket），本期端到端落地 |
| D4 | 沙箱镜像 | 三份 Dockerfile 入仓库；测试用 ImageFromDockerfile 构建，生产 compose 从仓库构建 |
| D5 | 队列消费 | 定时轮询兜底（fixedDelay=1s）+ 提交后唤醒；启动复位遗留 RUNNING→PENDING |
| D6 | 挂账清偿 | 并发锁 / 有提交不可移出 / `_` 转义对照行，随本计划同 PR |

沿用路线图既定约束：<200 学生单机；纯规则无 LLM；隐藏测试点零泄漏；多次提交全保留取最高分；Java 时限 ×2。

## 3. 数据模型（V6__judging.sql）

```sql
CREATE TABLE `submission` (
    `id`                    BIGINT      NOT NULL AUTO_INCREMENT PRIMARY KEY,
    `problem_id`            BIGINT      NOT NULL,
    `user_id`               BIGINT      NOT NULL,
    `assignment_id`         BIGINT      NULL COMMENT '练习提交为 NULL',
    `assignment_problem_id` BIGINT      NULL COMMENT '练习提交为 NULL',
    `language`              VARCHAR(10) NOT NULL COMMENT 'C/CPP/JAVA/PYTHON',
    `code`                  MEDIUMTEXT  NOT NULL COMMENT '源码原文 ≤64KB',
    `status`                VARCHAR(20) NOT NULL DEFAULT 'PENDING'
                            COMMENT 'PENDING/RUNNING/AC/WA/TLE/MLE/RE/CE/SYSTEM_ERROR',
    `score`                 INT         NULL COMMENT '练习恒NULL; 作业: AC=题分 否则0',
    `passed_count`          INT         NOT NULL DEFAULT 0,
    `total_count`           INT         NOT NULL DEFAULT 0,
    `time_used_ms`          INT         NULL COMMENT '各测试点最大用时',
    `memory_used_mb`        INT         NULL COMMENT '各测试点最大内存(采样峰值)',
    `is_late`               TINYINT     NOT NULL DEFAULT 0,
    `submitted_at`          DATETIME    NOT NULL DEFAULT CURRENT_TIMESTAMP,
    KEY `idx_submission_user` (user_id),
    KEY `idx_submission_problem` (problem_id),
    KEY `idx_submission_ap` (assignment_problem_id)
) ENGINE=InnoDB;

CREATE TABLE `judge_task` (
    `id`            BIGINT     NOT NULL AUTO_INCREMENT PRIMARY KEY,
    `submission_id` BIGINT     NOT NULL,
    `status`        VARCHAR(10) NOT NULL DEFAULT 'PENDING' COMMENT 'PENDING/RUNNING/DONE/FAILED',
    `retry_count`   INT        NOT NULL DEFAULT 0,
    UNIQUE KEY `uk_judge_task_submission` (submission_id)
) ENGINE=InnoDB;

CREATE TABLE `judge_detail` (
    `id`             BIGINT      NOT NULL AUTO_INCREMENT PRIMARY KEY,
    `submission_id`  BIGINT      NOT NULL,
    `test_case_id`   BIGINT      NOT NULL,
    `point_index`    INT         NOT NULL COMMENT '1-based，按 test_case.id 升序',
    `status`         VARCHAR(4)  NOT NULL COMMENT 'AC/WA/TLE/MLE/RE',
    `time_used_ms`   INT         NULL,
    `memory_used_mb` INT         NULL,
    `message`        VARCHAR(2000) NULL COMMENT 'RE stderr尾段/WA摘要; 读侧按可见性过滤',
    KEY `idx_detail_submission` (submission_id)
) ENGINE=InnoDB;
```

外键策略不物理建 FK（同既有表先例，引用完整性由 service 层保证）。判定来源：

- **score**：`AC` 且有 assignment 上下文 → 该 `assignment_problem.score`；`AC` 无上下文 → NULL；非 AC 有上下文 → 0。
- **passed_count / total_count**：CE 与 SYSTEM_ERROR 时 passed=0、total=N（N=该题测试点数）。
- **time/memory 聚合列**：仅成功产点的提交写入（max 各明细），CE/SYSTEM_ERROR 为 NULL。
- **is_late**：提交时刻处于 LATE_WINDOW（复用 `AssignmentStatus.of` 边界语义，isEqual 含宽限终点）→ 1；IN_PROGRESS → 0；仅作业路径参与此判定。

新增错误码（ErrorCode 追加）：

| 码 | 枚举 | 文案 |
|---|---|---|
| 40018 | SUBMISSION_TOO_FREQUENT | 提交过于频繁，请稍候再试 |
| 40019 | CODE_TOO_LARGE | 代码超出大小限制 |
| 40020 | PROBLEM_HAS_SUBMISSIONS | 该题已有学生的提交记录，无法从课程移出 |

## 4. 提交链路（POST /api/submissions）

一次请求走完九道门，任一失败即业务码拒绝，**不落任何行**：

```
①鉴权：仅 STUDENT（教师/管理员访问 → 403 Spring Security）
②目标分流校验（请求体二选一字段分流，双传/PAF 均 PARAM_INVALID）：
   作业路径 {assignmentProblemId}：
       assignment_problem 存在 ∧ assertEnrolled(course ACTIVE)
       ∧ is_published=1 ∧ AssignmentStatus：
           NOT_STARTED → 40300「作业尚未开始」
           CLOSED      → 40300「作业已截止，无法提交」
           IN_PROGRESS → 放行，is_late=0
           LATE_WINDOW → 放行，is_late=1
   练习路径 {problemId}：
       problem.is_public=1；私有题或不存在一律 40400（隐藏存在性）
③language ∈ Languages.ALL ∩ 该题 allowed_languages（交集为空同样拒绝，PARAM_INVALID）
④限流：同用户同目标（作业按 assignment_problem_id、练习按 problem_id 维度）
       最近一条 submission 的 submitted_at 在 10 秒内 → 40018
       （查 idx_submission_user 后过滤即可；不再新建设施）
⑤code UTF-8 字节数 ≤65536，越界 → 40019
⑥INSERT submission(PENDING) + judge_task(PENDING) —— 同一事务
⑦事务提交后异步触发 dispatch() 唤醒（失败静默，定时器兜底；响应不被阻塞）
⑧返回 {submissionId, status:"PENDING"}
```

补充语义：

- **并发提交**允许：前一次仍在 PENDING/RUNNING 不拦截新提交（多次提交全保留、成绩取最高是既定规则）。
- 教师把 `is_published` 关回 0：历史提交保留可查，新提交在②被拦（40400 隐藏）。
- 请求 DTO（valid 走 @Valid）：`{assignmentProblemId?, problemId?, language(@NotBlank), code(@NotBlank)}`，两目标键互斥校验在 service 内做。

## 6. 判题流水线（每任务一容器，容器内逐点 exec）

```
worker 领到任务：
①装载 submission + problem + 全部测试点（test_case.id 升序；point_index=序号1-based）
②创建容器（docker-java，语言映射对应镜像）HostConfig：
    Memory = memory_limit_mb + 运行时底座余量（C/CPP/PYTHON:+64MB，JAVA:+192MB）
    MemorySwap = Memory（禁swap）｜ PidsLimit=64 ｜ NetworkMode=disabled
    ReadonlyRootfs=true ｜ Tmpfs：/work 与 /tmp（rw,nosuid,size≈64MB）
③编译 exec（客户端墙钟 30s 上限）：
    C:     gcc -O2 main.c -o main
    CPP:   g++ -std=c++17 -O2 main.cpp -o main
    JAVA:  javac Main.java          （约定 public class Main）
    PYTHON: python -m py_compile main.py
    超时或退出码非零 → CE 终局：写回(passed=0,total=N, message=stderr截断≤2000)、销毁容器、结束
④逐测试点 i：单次 exec，stdin=input，stdout/stderr 收集
    客户端墙钟 effectiveLimit = timeLimitMs × (JAVA?2:1) + slack(500ms)，超时强杀该 exec
    ├─ 墙钟超时           → TLE，继续下一测试点
    ├─ OOMKilled/exit137  → MLE，继续
    ├─ 退出码非零         → RE（message=stderr 尾段≤2000字符），继续
    └─ 退出码 0           → OutputComparator.compare(expected, actual) → AC / WA
⑤汇总写回（单一事务）：judge_task=DONE + submission 终态 + judge_detail N 行
⑥finally 无条件 remove 容器（含异常路径）
```

关键实现语义：

- **输出比对器**：接口 `OutputComparator.compare(expected, actual)`，默认实现忽略每行行尾空白、忽略文末多余空行，其余精确匹配；接口即二期 Special Judge 扩展位。
- **MLE 只认 cgroup 击杀**（确定性高）：stats 流每 ~50ms 采样仅供 memory_used_mb 回显，不做软超限判定。
- **时间计量为客户端墙钟**：绝对值含少量开销，但题目时限按在线表现配置，提交间公平可比。
- **streaming 大输出**：stdout 输出上限 1MB，超出按 WA 处理（防御恶意刷输出）。
- **CE message 学生全文可见**（编译报错非测试数据，无泄漏面）。

## 7. 调度器与故障恢复

```
MspJudgeScheduler：
·@Scheduled(fixedDelayString="${msp.judge.poll-ms:1000}") + AtomicBoolean 重入护栏
·每轮开头 daemon 探活（docker-java ping）；不可达 → 本轮直接让出（任务留表=降级排队）
·领取循环：有空闲许可(Semaphore concurrent=3)且存在 PENDING 时
   原子 UPDATE 领任务标 RUNNING（update judge_task set status='RUNNING', where id=? and status='PENDING'，
   影响行数 1 才算领到——调度线程与唤醒触发可能并发争抢同一任务）
   → 提交 worker 线程池（固定 3 线程，Semaphore 控上限）执行 §6 流水线
·dispatch()：提交事务成功后调用，直接驱动一轮领取（不等下一 tick）
·worker 异常分类处置：
   业务终态（含 CE）                        → 正常写回 DONE
   基础设施异常（daemon失联/镜像缺失等）      → retry_count+1：
                                                <2 → 回置 PENDING 下轮重跑
                                                ≥2 → judge_task FAILED + submission SYSTEM_ERROR
                                                     （不计成绩、不锁提交，学生可重新交）
```

- **崩溃恢复**：应用就绪钩子把遗留 RUNNING 的 judge_task 复位回 PENDING，同步把对应 submission.status RUNNING 复位为 PENDING，自动续跑。
- 单机单实例假设：无线程间任务竞争面；UPDATE where status=PENDING 抢占已覆盖唤醒与定时并发窗口。

## 8. WebSocket 进度推送

- 新依赖 `spring-boot-starter-websocket`；STOMP 端点 `/ws/judge`（原生 STOMP，不做 SockJS 兜底）
- 握手拦截器从 CONNECT 帧头读取 Bearer JWT，复用现有 `JwtService` 验签 + 用户实时启用校验；未认证 CONNECT 一律拒绝
- 服务端定向投递 `convertAndSendToUser(userId, "/user/queue/judge-progress", event)`
- 事件载荷（JSON record，均含 submissionId）：

| type | 触发时机 | 附带字段 |
|---|---|---|
| JUDGING | worker 开始执行 | — |
| POINT | 每个测试点结束 | pointIndex, status |
| COMPILE_ERROR | CE 写库前 | message（编译报错全文） |
| FINISHED | 终态写库后 | status, score(可null), passedCount, totalCount |

- WebSocket 是纯通知通道：真相永远以 GET 接口为准，前端刷新/漏发均可自愈。

## 9. 学生读侧接口

### GET /api/submissions/my

参数：`assignmentProblemId` 或 `problemId` 二选一（双传/皆缺 → PARAM_INVALID）。
本人该目标的历史提交列表，倒序摘要项 `{id,status,score,isLate,language,submittedAt}`。
归属门：作业目标需 assertEnrolled；练习目标需 is_public。

### GET /api/submissions/{id}

本人提交详情（他人 id 一律 40400）：

- 公共字段：`id, language, code(本人物理可读), status, score, passedCount, totalCount, timeUsedMs, memoryUsedMb, isLate, submittedAt`
- 明细按可见性过滤后的测试点视图：
  - 样例点（is_sample=true）：`pointIndex, status, timeUsedMs, memoryUsedMb, input, expectedOutput, message`
  - **隐藏点：`pointIndex, status, timeUsedMs, memoryUsedMb` 四字段——input/expectedOutput/message 物理不出现在响应 JSON 中**（延续计划 3 零泄漏红线）

## 11. 安全要点汇总

| 面 | 措施 |
|---|---|
| 沙箱隔离 | 一次性容器判完即毁；非 root(uid 2000)；`--network disabled`；内存上限+禁 swap；pids-limit 防炸弹；只读根文件系统 + tmpfs 小可写区 |
| 数据泄漏 | 隐藏测试点 input/output/message 不进入任何学生可达响应（出参构造层面物理隔离）；RE stderr 仅样例点下发 |
| 横向越权 | 提交读侧严格 owner 过滤（user_id+归属链），他人 id 一律 40400 |
| 注入面 | 语言键白名单枚举直通；代码文件以 docker-java API 直接字节写入挂载，不经 shell 拼接 |

## 13. 计划 4 挂账清偿（同 PR）

1. **并发锁加固**：`CourseSelectionService.remove()` 与 `addProblems()` 事务头加 `SELECT course … FOR UPDATE`，形成每课程互斥锁（锁序恒 course 先）。
2. **移出保护加严**：判定条件为——该题被本课程（`course_id` 匹配）的任一 `assignment_problem` 引用，且该引用下已存在任意一条 `submission` 记录 → 返回独立错误码 40020 `PROBLEM_HAS_SUBMISSIONS`（比 40016 更收紧，仅练习路径的无锚提交不计入此判定）；无提交引用则维持既有 40016 检查不变。两检查按「先 40020 后 40016」顺序执行。
3. **LikeUtilsTest 补严**：追加 `_` 单独作为待转义字符的显式对照断言行。

> 注 1：因 D2「整题全对制」，无需迁移 test_case 表新增列。
> 注 2：引用不变量「作业引用 ⊆ 课程选题引用」由 addProblems 写入侧维持，`ProblemService.delete` 的 40015 检查因此无需改动。
