## 1. 背景与问题

一期交付了完整在线评测：学生每份提交的**源码与语言**已持久化（`submission.code/language`），教师端有作业/成绩册/提交历史。但教师**无法发现学生间相互抄袭**——只能人工逐份对比代码，低效且不可靠。高校编程作业场景，最典型抄袭形态是「同班同学之间复制粘贴/微改（改名、改排版、改提示文案）」，需要一次一键式同题两两比对报告。

## 2. 需求确认结论（已与需求方逐项拍板）

| # | 决策点 | 结论 |
|---|---|---|
| 1 | 比对分组 | **按作业内每题同班互比**：教师进入某作业某题，看该题全班学生两两相似度 |
| 2 | 参与样本 | 每题每生取**最高分提交**（AC 优先；同分取最新），与该题其余学生最高分互比 |
| 3 | 算法深度 | **真 AST 树比对**：Tree-sitter（bonede Java 绑定）解析 C/C++/Java/Python；标识符与数字/布尔归一为占位、**字符串字面量保留原文**；对归一化后的结构内容流算相似度 |
| 4 | 结果呈现 | 教师端「查重报告」页：疑似对列表（相似度百分比 + 等级标签 + 可调阈值）→ 点开**左右分栏代码对比、相似片段高亮** |
| 5 | 可见性 | **仅教师可见**（学生端零展示，防他人代码泄露） |
| 6 | 计算模式 | **即时计算 + 进程内缓存**（提交不可变 ⇒ 指纹可缓存；≤200 人每题 ~2 万对以内秒级可答），不落报告表 |

## 3. 技术选型与可行性结论

- **解析器**：`io.github.bonede:tree-sitter`（core 0.24.4）+ `tree-sitter-c 0.23.2 / cpp 0.23.4 / java 0.23.4 / python 0.23.4`。bonede 绑定将各语言语法与原生库打包进 jar，运行期自动解包；语法覆盖全、**容错解析**（语法错误不抛异常，产生 error 节点）——正适合学生半截/微错代码。
- **原生库落盘目录**：原生库默认解到 `~/.tree-sitter`，**受部署环境目录策略影响**；通过系统属性 `-Dtree-sitter-lib=<dir>` 可覆盖。本工程约定：
  - 测试：pom surefire `<argLine>-Dtree-sitter-lib=${project.build.directory}/tree-sitter-lib</argLine>`（落在 `server/target/`，随构建目录走，`mvn test` 开箱即用）；
  - 运行：`java -Dtree-sitter-lib=<部署目录>/tree-sitter-lib -jar msp-server.jar ...`（部署文档注明）。
- 已实测：macOS arm64 原生库加载成功，C 解析出 `function_definition`、Java 解析出 `method_declaration`。

## 4. 算法设计（AST → 抗改名指纹 → 相似度）

### 4.1 解析与归一化

```
源码 --TreeSitter--> 语法树(CST)
    --walk--> 规范化 token 流
```

对每个语法节点产出两类 token：

| 节点类别 | 处理 | 例 |
|---|---|---|
| 注释/空白 | 跳过（不进流） | `// xxx` |
| 标识符（变量/函数/类名） | 归一为 `ID` | `sum`、`getTotal` → `ID` |
| 数字/布尔字面量 | 归一为 `NUM` | `100`、`true` |
| 字符串字面量 | **保留原文** | `"请输入"` 保留（防「只改提示语」蒙混） |
| 其它节点（结构类型名） | 按节点类型产出 | `function_definition`、`for_statement` … |

产出：**大小写不敏感的结构-内容 token 序列**（如 `[function_definition, ID, NUM, ..., string:"请输入"]`）。该序列天然抗「改名/重排空白/注释」；保留字符串使「只改提示文案」被识破。

**注意口径**：token 是**语言中立**的（同题 C 与 C++ 的可比），但对不同语言程序天然结构差异大 ⇒ 误报概率低；报告仍给语言标注便于教师判断。

### 4.2 相似度

- 指纹：对 token 序列取 **5-gram 滚动窗口哈希集合**（去重）。
- 两两相似度：
  ```
  sim(A,B) = |win(A) ∩ win(B)| / |win(A) ∪ win(B)|          （shingle Jaccard）
  兜底：A 或 B 序列过短（<6 token）时退化为逐 token Jaccard；完全同序同内容 ⇒ sim=1
  ```
- 语义锚定：sim ∈ [0,1]；仅结构相同而标识符不同的程序趋近 1（抗改名成立）；不同算法趋近 0。阈值可调，默认 **0.80 及以上 = 「高疑似」**，0.5–0.8 = 「关注」，<0.5 默认不入报告（教师可下调阈值查看更弱相似）。
- 复杂度：每题 200 名学生 ≈ 19900 对；每对为集合交并（各 ~10³ 级哈希），全程秒级；指纹缓存后毫秒级。

### 4.3 取样规则（每生该题最高分提交）

```
同 (assignmentId, assignmentProblemId) 下该生全部 submission：
   排序键 = (isAC ? 1 : 0, score, submittedAt) 降序，取第 1 条
```
- 仅统计**已判终态**提交；PENDING/RUNNING 不参与（等判完刷新重查即可）。
- 提交不可变 ⇒ 指纹按 submissionId 进程内缓存（LRU 上限保护），无失效问题。

## 5. 后端结构与端点

领域包 `com.mashangping.plagiarism`：

```
plagiarism/
  CodeParser.java            # 接口：parse(lang, code) → List<String> 归一 token 流
  TreeSitterCodeParser.java  # TreeSitter 实现（按 JudgeLanguage 选语法；解析失败/error 节点宽容处理）
  CodeFingerprint.java       # 指纹：shingle 集合 + token 长度等元数据
  SimilarityEngine.java      # 静态工具：Jaccard/兜底、0~1 归一
  PlagiarismService.java     # 取样(最高分)+缓存+归属校验+两两比对 → 报告
  PlagiarismController.java  # 教师端点（hasRole TEACHER）
  PlagiarismViews.java       # 报告 record：PairItem / StudentInfo（含 code 供对比）
```

### 端点（教师，均走归属链：作业属当前教师之课，越权 40400）

| 端点 | 说明 |
|---|---|
| `GET /api/assignments/{assignmentId}/plagiarism/problems/{problemId}?threshold=0.8` | 该作业内某题的查重报告：`items[]` 两两对（按相似度降序），对含 A/B 学生信息（学号/姓名/语言/得分/是否AC/最高分提交id）、`similarity`、`flag`(HIGH/MID) |
| `GET /api/assignments/{assignmentId}/plagiarism/problems/{problemId}/compare?submissionA=&submissionB=` | 指定两提交的对比数据：A/B 的 `code`+元信息（供前端左右分栏高亮，无需前端再拼装） |

无 DB 迁移：报告即时算、无新表（缓存进程内）。`Submission`/`submission.code` 直接复用。

## 6. 前端结构与端点消费（教师端）

```
frontend/src/pages/teacher/
  PlagiarismPage.tsx        # /teacher/assignments/:assignmentId/plagiarism/:problemId
  PlagiarismCompare.tsx     # 左右分栏代码对比 + 相似行高亮（疑似雷同片段）
  PlagiarismPage.test.tsx
frontend/src/api/plagiarismTypes.ts   # 报告/对比 TS 类型
```

- **入口**：`AssignmentDetailPage`（教师作业详情）的题目清单里每题行新增「查重」按钮 → 路由 `/teacher/assignments/:assignmentId/plagiarism/:problemId`（作业详情问题列表已含 problemId/title）。
- **报告页**：顶部题名 + 阈值输入（默认 0.8，回车刷新）；表格 = 学生A vs 学生B（学号/姓名/语言/得分）+ 相似度进度条与颜色标签（≥阈值红「高疑似」，≥0.5 橙「关注」）；按相似度降序。
- **对比页/抽屉**：点击一对 → 左右两栏并排展示双方最高分提交源码；**雷同行高亮**（左侧用「右侧也出现的规范化行」标记红色右栏对称），并给出相似度/语言/得分。
- 测试：报告页渲染（mock GET）、行点击打开对比、仅教师路由（沿用 teacher 测试 harness 风格）。

## 7. 红线与全局约束

- **教师归属链**：作业属当前教师之课，否则 40400；复用 assignment 域既有校验（不复制其它 owner 逻辑）。
- **学生不可见**：查重端点全部 `hasRole('TEACHER')`；学生端零查重 UI/API。
- **不新增 Flyway 迁移**；不改判题链路。
- Java 17（无 JDK21 API）；前端 tsc strict、文案中文。
- 字符串保留是**设计**（识别改提示语），非泄漏——结果只对教师展示代码与相似度。

## 8. 测试策略

- 纯单测（无需 Docker）：归一化（改名不变/注释排版不变/改字符串变化）、shingle Jaccard 数值、取样排序（AC优先/同分取新/忽略未判）、短代码兜底、报告降序。
- 集成测试（Testcontainers）：教师归属校验 40400、非教师 403、报告含正确对（两生同解改名 vs 不同算法），compare 端点返回双方 code。
- 前端：报告页 + 对比渲染 + 路由测试。
- 运行备注：测试解析需原生库，pom surefire 已通过 `-Dtree-sitter-lib` 落到 `server/target/tree-sitter-lib`，`mvn test` 无需额外参数。
