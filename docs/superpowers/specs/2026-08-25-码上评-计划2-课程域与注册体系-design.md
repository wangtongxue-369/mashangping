# 码上评 · 计划 2 设计：课程域与注册体系

日期：2026-08-25
状态：已与需求方逐节确认
前置：计划 1（脚手架与认证用户体系）已完成并合入 main；本设计基于总规格 §3 路线图中的 P0 教学底座细化，并**修订**其中两处需求（见 §2 修订说明）

## 1. 背景与目标

计划 1 交付了认证、用户管理与安全链。计划 2 打通教学底座核心：学生能自助注册进系统，教师能建课并按学号把学生拉进课程——**包括尚未注册的学生**：教师先行预置名单，学生日后注册完成即自动出现在课程中。

同时落地计划 1 遗留的规格级决策：**JWT 实时吊销**。

## 4. 数据模型（V2 迁移，单文件）

```sql
-- 学号唯一：学生身份锚点（教师/管理员 student_no 为 NULL，MySQL 唯一索引允许多 NULL）
ALTER TABLE `user`
    ADD UNIQUE KEY `uk_user_student_no` (`student_no`);

CREATE TABLE `email_verification` (
    `id`         BIGINT       NOT NULL AUTO_INCREMENT PRIMARY KEY,
    `email`      VARCHAR(100) NOT NULL,
    `code`       CHAR(6)      NOT NULL COMMENT '6位纯数字',
    `purpose`    VARCHAR(20)  NOT NULL DEFAULT 'REGISTER',
    `expires_at` DATETIME     NOT NULL COMMENT '15分钟有效期',
    `created_at` DATETIME     NOT NULL DEFAULT CURRENT_TIMESTAMP,
    `used`       TINYINT      NOT NULL DEFAULT 0,
    KEY `idx_emailverify_email` (`email`, `created_at`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci;

CREATE TABLE `course` (
    `id`          BIGINT       NOT NULL AUTO_INCREMENT PRIMARY KEY,
    `name`        VARCHAR(100) NOT NULL COMMENT '课程名',
    `term`        VARCHAR(50)  NOT NULL COMMENT '学期，如 2025-2026-1',
    `description` VARCHAR(500) NULL,
    `teacher_id`  BIGINT       NOT NULL COMMENT '授课教师，单师制',
    `created_at`  DATETIME     NOT NULL DEFAULT CURRENT_TIMESTAMP,
    `updated_at`  DATETIME     NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
    KEY `idx_course_teacher` (`teacher_id`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci;

CREATE TABLE `enrollment` (
    `id`           BIGINT      NOT NULL AUTO_INCREMENT PRIMARY KEY,
    `course_id`    BIGINT      NOT NULL,
    `student_id`   BIGINT      NULL COMMENT '已激活关联账号；待激活为NULL',
    `student_no`   VARCHAR(30) NOT NULL COMMENT '身份锚点',
    `student_name` VARCHAR(50) NOT NULL COMMENT '拉人时姓名快照，供教师核对',
    `status`       VARCHAR(10) NOT NULL DEFAULT 'PENDING' COMMENT 'PENDING/ACTIVE',
    `enrolled_at`  DATETIME    NOT NULL DEFAULT CURRENT_TIMESTAMP,
    UNIQUE KEY `uk_enrollment_course_no` (`course_id`, `student_no`),
    KEY `idx_enrollment_student_id` (`student_id`),
    KEY `idx_enrollment_pending_no` (`student_no`, `status`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci;
```

要点：
- `enrollment.student_no` 是身份锚点：教师只凭学号拉人；注册时按 `(student_no, status='PENDING')` 一次性激活全部匹配行
- `student_name` 为拉人时快照；已激活成员展示以账号 `real_name` 为准
- 已注册学生被拉人：查 `user` by student_no → 直接 ACTIVE；未注册 → PENDING
- 同一学生可出现在多门课（各课独立行）

## 5. API 设计

### 公开接口（permitAll）

| 接口 | 行为 |
|---|---|
| `POST /api/auth/register/code` `{email}` | 域名白名单校验 → 限频检查（同邮箱 60 秒 1 条、单日 10 条）→ 生成 6 位数字验证码落库（15 分钟过期）→ 发信 |
| `POST /api/auth/register` `{email, code, studentNo, realName, password}` | 验码 → 建 STUDENT 账号 → 激活所有学号匹配的 PENDING 名单 → 签发 token（注册即登录）。全程一个事务 |

密码规则沿用计划 1：6~64 位。学号须匹配 `\w{3,30}` 且未被已有账号占用（40013）。

### 学生端

| 接口 | 行为 |
|---|---|
| `GET /api/courses/my` | 我加入的课程（仅 status='ACTIVE' 的 enrollment 对应课程） |

### 教师端（service 层归属链校验）

| 接口 | 行为 |
|---|---|
| `POST /api/courses` `{name, term, description?}` | 建课 |
| `GET /api/courses?page&size&keyword` | 我教的课，分页+名称关键词 |
| `GET /api/courses/{id}` / `PUT /api/courses/{id}` | 详情 / 修改 |
| `POST /api/courses/{id}/students` `{studentNo, studentName}` | 按学号单人添加：有账号→ACTIVE；无→PENDING；已在班→40401 |
| `POST /api/courses/{id}/students/import` (multipart) | Excel 批量，语义同上，见 §8 细则 |
| `GET /api/courses/{id}/students?status=&keyword=&page&size` | 成员列表：status 筛选 PENDING/ACTIVE；keyword 匹配学号/姓名快照/账号姓名 |
| `DELETE /api/courses/{id}/students/{enrollmentId}` | 移除成员（两种状态均可） |

## 6. 权限边界

1. 课程归属链：`{id}` 类操作校验 `course.teacher_id == 当前用户 uid`；不匹配返回 **40400「课程不存在」**（隐藏存在性，防探测枚举）
2. 学生侧仅能触达 `enrollment.student_id = 自身 uid` 的数据
3. ADMIN 不进课程域
4. 角色控制沿用 `@PreAuthorize`（TEACHER/STUDENT 各接口显式标注）；ADMIN 因角色层级包含关系需注意：Spring 的 `hasRole('TEACHER')` 不含 ADMIN——课程域教师接口明确限定 `hasRole('TEACHER')`，ADMIN 不越权代管

## 7. JWT 实时吊销改造（D1）

```
JwtAuthFilter 改造后流程：
Bearer 解析 → TokenPayload(uid,…)
  → UserAuthCache.get(uid)：命中(≤30s)直接用
  → 未命中：userMapper.selectById(uid)
      ├─ null 或 enabled=false → SecurityContextHolder.clearContext() → 401
      └─ 正常 → 快照(role) 入缓存
  → authorities = ROLE_{库内最新role}（不再信任 token 内声明）
```

- `UserAuthCache`：手写 `ConcurrentHashMap<Long, Entry>`，TTL 30_000ms，上限 1000 条超限全清；无新依赖
- 管理操作（停用/启用/重置密码）后调用 `invalidate(uid)` 即刻生效
- 安全增益：停用即刻生效（原 24h 窗口消除）；角色变更即刻生效

## 8. Excel 导入细则

- 限制：仅 `.xlsx`；≤500 行；首行表头必须为 `学号｜姓名`（A/B 两列）
- 行结果三分类：
  - **直接激活**：学号已有 STUDENT 账号 → 建 ACTIVE enrollment
  - **待激活**：无账号 → 建 PENDING enrollment（存姓名快照）
  - **跳过**：文件内学号重复 / 该学号已是本班成员（任一状态）——不计入失败
- 行级失败原因：学号为空或格式错（`\w{3,30}`）、姓名为空、超长
- 文件级失败（40014）：非 .xlsx、空文件、超 500 行、表头不符
- 响应体：`{totalRows, activated, pending, skipped, failures:[{row, reason}]}`；部分成功模式，坏行不影响好行
- 解析库：EasyExcel；同步处理（200 行秒级）

## 9. 邮件与验证码模块

```
MailSender 接口：void send(String to, String subject, String textBody)
├─ SmtpMailSender：包装 spring-boot-starter-mail 的 JavaMailSender；
│   msp.mail.enabled=true 时生效；默认 465 端口 SSL（mail.smtp.ssl.enable=true）
└─ LoggingMailSender：enabled=false 时生效（开发默认，只打日志）

VerificationCodeService：
├─ issue(email)：白名单校验(40010) → 限频查表(40012) → 生成6位随机数字
│   → email_verification 落库(expires_at=now+15min) → 发信（正文含码与有效期提示）
└─ verify(email, code)：匹配该邮箱最新未用未过期记录 → 置 used=1；否则 40011
```

- 配置项：`msp.mail.{enabled,host,port,username,password,from}`、`msp.school.email-suffixes[]`
- 清理：每日定时任务删除 `created_at < now-7天` 的记录
- 发信失败处理：issue 全程事务外发信（先落库后发信）；SMTP 异常返回 50000 并记日志，验证码仍在有效期内可重发触发（受 60 秒限频约束）

## 10. 错误码新增

| 码 | 常量 | 含义 |
|---|---|---|
| 40010 | EMAIL_DOMAIN_NOT_ALLOWED | 邮箱域不在学校白名单 |
| 40011 | EMAIL_CODE_INVALID | 验证码无效或已过期 |
| 40012 | EMAIL_CODE_RATE_LIMITED | 验证码发送过于频繁 |
| 40013 | STUDENT_NO_CONFLICT | 学号已被占用 |
| 40014 | EXCEL_FORMAT_ERROR | 导入文件不合法 |
| 40401 | ENROLLMENT_DUPLICATE | 该学号已在课程中 |

复用：40400 NOT_FOUND（课程/成员不存在或非属主）、PARAM_INVALID/BAD_CREDENTIALS 等既有码。
