# 码上评 · 计划 9 设计（前端大优化 · 课程工作台 + 全站精品化 + 功能打通）

日期：2026-08-28
状态：brainstorm 五项已拍板（课程工作台形态 / 图表范围全选五类 / 教师端整体升级 / @ant-design/plots / 允许扩后端聚合端点）

> 关联：一期/二期已交付功能（课程/学生/作业/题库/成绩册/提交/查重）。本计划把散落的教师页收拢为「以课程为中心的二级界面」，并以图形化看板呈现班级数据，同时把教师端视觉升级到与学生端一致的浅色精品风，理顺全站互链。
> 图形数据均来自既有表（course/enrollment/assignment/assignment_problem/problem/submission/judge_detail/test_case）的**读聚合**，无新表、无迁移。

## 1. 目标与问题

现状：教师端是扁平页面（课程页直连学生名单子页、无课程中枢；作业/成绩册/查重各自散落）；教师端仍是老式深色布局而学生端已浅色精品化；无任何图表库；页面间缺面包屑/互链。教师面对一门课时缺少「一站式工作台」查看班级健康度与快速管理。

## 2. 范围

### 2.1 做（In scope）
1. **课程工作台**（新页 `/teacher/courses/:courseId`，`CourseConsolePage`）：
   - 顶部概览卡：学生数 / 作业数(已发布) / 课程选题数 / 全班平均分(最近作业) / 查重高疑似对数；
   - **图形看板**（@ant-design/plots）：成绩趋势(各作业平均/最高/最低)、分数段分布(选中作业)、每题 AC 率条形、提交状态环形、按天提交时间线、查重风险汇总（疑似对数列表，点击直达该题查重页）；
   - **业务入口卡片**：学生名单 / 作业管理 / 该作业成绩册 / 题库（进课程选题视角）等快捷入口。
   - CoursesPage 课程名改为进入工作台（学生名单深链保留在子路由）。
2. **后端聚合端点**（教师归属，越权 40400；读-only）：
   | 端点 | 返回 |
   |---|---|
   | `GET /api/courses/{courseId}/analytics/overview` | 学生数/作业数/已发布/选题数/全班平均分(最近一已发布作业,缺提交记0)/查重 HIGH 对数 |
   | `GET /api/courses/{courseId}/analytics/score-trend` | 每个作业：id/title/start/due/avg/max/min/参与学生数 |
   | `GET /api/assignments/{assignmentId}/analytics/score-distribution` | 分数段桶 [{label,count}]（0-59/60-69/70-79/80-89/90-100，缺提交=0） |
   | `GET /api/courses/{courseId}/analytics/ac-rate` | 每个作业题：assignmentId/problemId/problemTitle/acStudents/submittedStudents/rate |
   | `GET /api/courses/{courseId}/analytics/status-distribution` | 该课提交按状态计数（可带 assignmentId 过滤） |
   | `GET /api/courses/{courseId}/analytics/submission-timeline` | 按天提交量（近30天有提交的日） |
   | `GET /api/courses/{courseId}/analytics/plagiarism-risk` | 每个作业题的 HIGH/MID 疑似对数（复用查重引擎按需即时算） |
3. **教师端整体浅色精品化**：TeacherLayout 换白色顶栏（与 StudentLayout 一致）+ 内容区浅灰 + 每页用 `.msp-card`/统一页头/空态/错误态/加载态；保持既有文案与测试。
4. **功能打通**：面包屑与互链（课程工作台 ↔ 学生名单/作业/成绩册/题目详情/查重；作业详情↔成绩册/提交/查重；题库问题行链接课程选题视角等）；补齐明显的返回链路。

### 2.2 不做（Out of scope）
- P3 学生反馈页/看板（学生端不消费本计划图形）；ADMIN 控制台。
- 把图表数据落库/定时任务（全部即时读聚合 + 前端缓存即可）。
- 视觉细节的过度定制（不引入设计 token 体系），只用既有 global.css 扩展少量类。

## 3. 技术选型
- **图表库**：`@ant-design/plots`（antd 同族 G2，风格统一）。按需引入组件（`lazy` 路由避免主包过大；图表页组件 `React.lazy` 或 dynamic import）。
- 后端沿用 Spring/MyBatis-Plus；聚合按「**小数据内存聚合**」（<200 学生规模，先查出对象再流式计算，纯函数可单测，SQL 免写复杂 GROUP BY）为主，个别计数用 wrapper 聚合。
- 前端继续 TanStack Query + axios 单例 + `.msp-card` 等既有样式基座。

## 4. 页面信息架构（改造后教师端）
```
/teacher
├─ courses                   课程列表（浅色新布局）→ 点课程名 → course console
├─ courses/:courseId         课程工作台（新）：概览卡 + 看板 + 入口卡
├─ courses/:courseId/students 学生名单（保留；工作台可进）
├─ courses/:courseId/assignments 作业管理（保留；工作台可进）
├─ assignments/:assignmentId  作业详情（回链=所属课程工作台）
├─ assignments/:assignmentId/{submissions|gradebook|plagiarism/:problemId}（回链=作业详情）
├─ problems / problems/:problemId 题库（浅色化）
```

## 5. 语义与红线（沿用）
- 聚合端点全部 `hasRole('TEACHER')` 且归属校验（course.teacher_id==当前教师，否则 40400）；
- 缺提交学生按 0 计入平均/分布（与成绩册口径一致：`total`=各题 bestScore 之和，无 cell 视为 0）；
- AC 率口径：rate = 该作业题「最高分提交为 AC 的学生数 / 有提交的学生数」（无提交学生不计入分母）；
- 隐藏点等判题细节不进入聚合端点（只用 submission 级状态/score）；
- Java17；无 Flyway；前端 tsc strict。

## 6. 测试策略
- 后端：纯单测覆盖聚合纯函数（平均/桶/AC率/状态/时间线去重）；IT 覆盖归属 40400 与空数据不报错、非空数据数值抽样断言。
- 前端：图表页测试 mock `@ant-design/plots`（jsdom 无 canvas）与 client；断言概览卡数值/入口卡路由/图表数据 props；既有页面重构后回归原有文案断言。
- 构建门禁 + 全量回归（前端 vitest/tsc/build，后端 mvn test）。
