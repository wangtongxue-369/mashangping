# 计划10 · 前端 UI/UX 审查整改（P0~P3 全量）设计规格

- 日期：2026-09-06
- 需求来源：`docs/2026-09-06-前端-UIUX-审查报告.md`（后称「审查报告」）；本规格把报告 P0~P3 修复建议落为可执行行为契约
- 范围：前端为主，允许后端配合（名称字段、学生作业上下文、判题明细回显、重排/CSV 等）
- 相关文档：计划7/8/9 spec（学生端/查重/工作台）；CLAUDE.md

## 1. 现状问题一句话

单页完成度高，**页面之间欠连贯**：学生注册闭环缺失、ADMIN 登录死胡同、深链页无课程/作业名称上下文、教师端返回链/标题/状态样式多套并存、作业状态不贯穿作答流程、多处「接口失败」被当「空数据」展示、判题明细缺「你的输出」、若干低频便利功能缺位。

## 2. 全局约束（延续仓库纪律）

- 业务规则只动展示与信息架构，不触碰「隐藏测试点零泄漏」红线：学生视图不得新增泄露隐藏点输入/输出；现有「通过 X/Y、隐藏点按序枚举状态/用时/内存」口径维持不变（属既往已验收口径）。
- 越权一律 40400（存在性隐藏）；教师端点保持 `@PreAuthorize(TEACHER)`；学生作业门禁保持 `assertEnrolled → 已发布 → 已过 start_at`。
- Java 17（不用 JDK21 API）；Flyway：已提交迁移不可改，本计划允许新增 **V7__judging_actual_output.sql**（唯一新增列场景，理由见 §7.2）。
- 前端 tsc strict（noUnusedLocals/noUnusedParameters）；中文文案；conventional commits，描述中文；一任务一提交。
- 测试先行：后端单测/IT、前端同目录 `*.test.tsx`（vitest+Testing Library）。

## 3. P0 修复规格

### 3.1 学生注册闭环（审查 H1）

- 登录页加「没有账号？注册学生账号」链接 → 新路由 `/register`（公开，不走受保护布局；若已登录访问则仍显示注册页，注册成功覆盖会话）。
- 注册页表单（一次成型，非多步 wizard）：
  - 邮箱 + 「发送验证码」按钮：POST `/api/auth/register/code`；成功后按钮进入 60s 倒计时禁用；页面注明「仅限学校邮箱（xxx 后缀）」与「由教师在课程中导入过学号的同学，注册后自动加入对应课程」。
  - 验证码（6 位数字）、学号（3~30 位字母数字下划线）、姓名（≤50）、密码/确认密码（6~64 位且两次一致）。
  - 提交 POST `/api/auth/register`；成功即自动登录（后端直接回 token+user），跳 `/student/courses`。
  - 失败展示后端 message（40010 域名白名单/40011 验证码/40012 频率/40013 学号占用/40017 邮箱占用等），不清空邮箱与学号。
- `useAuth.login` 改为返回 `AuthUser`，供调用方按角色分支。

### 3.2 ADMIN 登录不再死胡同（审查 H2）

- 登录成功后若 role === `ADMIN`：提示「管理员功能建设中，请使用教师或学生账号登录」，随即清会话留登录页（不进入教师空端踩 403）。
- 教师端受保护页：保持现状（非本计划补 ADMIN 端）。

### 3.3 全站课程/作业名称上下文（审查 H3）与 CodingPage 原始 ID 移除

后端：
- `GET /api/assignments/{id}` 由「仅教师」改为角色分流：TEACHER 行为不变；STUDENT 分支返回新 `AssignmentViews.StudentAssignmentHeader`：
  `(courseId, courseName, assignmentId, title, status, startAt, dueAt, lateDays, problemCount)`，门禁 = 已发布 + 已选课（`assertEnrolled`），不要求已过 start_at（列表页也能用于展示未开始说明）。
- `AssignmentViews.TeacherDetail` 增 `courseName`（教师详情页/子页标题可用；已有 courseId）。

前端（学生）：
- 课程作业列表页：标题/页眉呈现课程名（经 `GET /courses/my` 查得，深链也成立）；保留返回「我的课程」。
- 作业题目列表页（`AssignmentProblemsPage`）与编码页（`CodingPage`）：并行拉 header 提供「课程名 / 作业名」上下文与作业状态；**CodingPage 顶部的 `课程 {id} / 作业 {id}` 原始 ID 文本删除**，改为名称上下文 + 状态徽标。
- 自由练习不受影响（无课程概念）。

## 4. P1 修复规格

### 4.1 作业状态贯穿作答流程（审查 H5）

- 数据：学生端题目列表/编码页经 3.3 的 header 获得 `status/dueAt/lateDays/startAt`。
- 表现（统一组件行为，作业与练习复用同一工作区组件）：
  - `AssignmentProblemsPage`：状态徽标展示；`CLOSED` 顶部 Alert「作业已截止，仍可查看题目与历史，不可再提交」；`LATE_WINDOW` 顶部 Alert「已过截止时间，仍可提交，将标记为迟交」；`IN_PROGRESS` 且未截止可显示截止倒计时（每秒刷新，格式 `HH:mm:ss`，不足 1 天显 `D 天 HH:mm:ss`）。
  - 编码页/CodingWorkspace：`CLOSED` 时「提交评测」按钮禁用并 tooltip 说明；`LATE_WINDOW` 每次提交前 `Modal.confirm`「已过截止时间，本次提交将标记为迟交，确定提交？」；练习模式无上述门禁。
- 后端无需改提交门禁（现有兜底已正确，前端只是提前告知，避免写完全部代码才发现白费）。

### 4.2 错误 vs 空数据区分（审查 H4）

- 课程工作台 `CourseConsolePage`：任一分析查询失败（40400/5xx）→ 页顶 Alert「看板数据加载失败」+「重试」（重新拉取全部失败查询），各卡不渲染误导性全 0；单查询失败不得影响其余成功卡。
- 编码区提交历史（CodingWorkspace）：区分「暂无提交」空态（保留引导文案）与「加载失败」（提示 + 重试按钮，不再显示误导空态文案与 `—` 最高分）。
- 学生「我的课程」：查询失败显示错误卡 + 重试（不再静默渲染「你还没有加入任何课程」空态）。

### 4.3 得分/最高分语义（审查 3.4）

- 练习模式（后端得分恒 null）：**隐藏「我的最高分」标签**，改显「已通过 N 次」（history 中 AC 条数）；提交记录「得分」列改显 `—` 且有列尾说明「练习不计分」。
- 作业模式：标签「我的最高分：{bestScore}/{满分}」；配色按 `bestScore === null` 灰、`=== 满分` 绿、`0` 红、其余橙，杜绝「0 分还亮绿」；满分由题目题分 `score` 传入（作业题详情有）。
- 一句话口径说明放练习/作业题面区小字（「练习不计分；作业全对得该题满分」）。

### 4.4 导航/返回（审查 二 与 P1 行 2）

教师端统一三层面包屑：`全部课程 / {课程名}(→课程工作台) / {当前页}`；进入点为课程列表、工作台、学生名单、作业管理、作业详情、提交、成绩册、查重汇总。
- `AssignmentsPage`（课程作业管理）补返回/面包屑（当前缺失）。
- `CourseStudentsPage`「返回」改为回课程工作台（原来一步跳列表顶层）；`CourseConsolePage` 从列表/子页进入时都能回到正确层级。
- `ProblemDetailPage` 保留来路：从作业详情题目行进入时显示「← 返回作业」+ 面包屑定位到作业；默认入口仍「← 返回题库」。
- 学生端链式返回已正确，仅统一视觉（文本按钮 + `←`）与名称上下文。
- 样式收敛为受控组件（见 P2 §5.1），本 P 阶段先补全跳转关系。

## 5. P2 修复规格

### 5.1 教师端公共常量 + 返回/标题样式收敛

### 5.2 学生名单/成绩册/CSV 便利（审查 3.8/3.12）

- `CourseStudentsPage`：

- **作业题重排**：后端 `PUT /api/assignments/{id}/problems/order`（body：按目标顺序的 problemId 列表，service 校验齐全后按序覆写 sort_order）；教师作业详情题目行加「上移/下移」按钮（首/尾禁用），操作后刷新。
- **查重阈值防抖**：`PlagiarismPage` 阈值 InputNumber 只改本地 state；「应用阈值」按钮（或显式确认）才更新 queryKey 触发重查，去掉每次步进即请求。
- **删除后果文案**：课程删除 Popconfirm 说明「其下作业/提交/成绩数据将一并删除，不可恢复」（与后端实际行为一致，实现时核对 CourseService.delete）；作业删除确认说明「该作业的提交与成绩数据将一并删除」；发布/进行中作业编辑提示「改动即时对学生可见」。
- **选题 Modal total 口径**：前端在已过滤已选题目时，分页器文案/提示注明「已选 N 题不在下列表」或改为本地分页（实现时选改动最小的正确方案，不糊弄 total）。

- **分页/筛选跨实体重置**：学生课程作业列表、教师作业/学生名单/提交历史等页在 courseId/assignmentId/筛选变化时重置 `page`（与 queryKey 变化联动，避免「空表 + 页码超出」）。
- 编码区易用（低风险顺手项）：语言切换改为**按语言分别保存编辑区内容**（同页内存态，切回保留）；空代码/原样模板代码提交前确认或禁用提交（作业与练习一致）；详情抽屉历史缓存陈旧问题通过提交成功后主动失效 + 重开强制刷新解决（不引入额外后端）。

## 7. 决策记录

### 7.1 学生名称上下文为何走新 header 而非改造列表返回结构

题目列表/题详情现返回裸数组/裸对象，改成包装对象会破坏既有后端 IT 与前端测试的响应形态、扩散面大。作业 header 走角色分流的 `GET /api/assignments/{id}`：形态新增、旧结构不动、学生也可用于「列表页/题目页/编码页」三处复用；课程名在 header 内一次取齐（CourseMapper 查名），避免每页调 `/courses/my` 猜测。

### 7.2 为何本计划允许 V7 迁移

「你的输出」必须持久化逐点 stdout：`judge_detail` 无此列，`message` 仅 RE stderr。CLAUDE.md 明文「改表结构一律新增 Vn__」；前几计划「无迁移」是因只读聚合，不构成全局禁令。V7 只增一列可空 MEDIUMTEXT，不动历史行；判题在 Docker 沙箱内跑（本机 dev 未启用 judge 时数据为 NULL，前端照常渲染）。SchemaTest（实体↔DDL 钉死）需同步更新。

### 7.3 未纳入项（维持现状，最终交付说明里列出）

- 注册「忘记密码」：后端无找回接口，超出前端范围。
- 教师隐藏点数量/学生通过率等新列需聚合新端点，本计划不做。
- WS 自动重连 / 断线提示、练习页通过率列、题目列表隐藏点数量列、MyCourses 卡扩展信息、拖拽排序（以上下移替代）：列为后续可选项，如时间允许再补。
