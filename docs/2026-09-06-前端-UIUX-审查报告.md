# 码上评 · 前端 UI/UX 审查报告

- 审查日期：2026-09-06
- 审查对象：`frontend/src` 全部页面/布局 + 全局样式与请求基建
- 交叉核对：后端作业状态机、提交门禁、注册体系、Excel 导入/CSV 导出格式等业务规则，验证「界面承诺」与「后端事实」的一致性
- 审查视角：UI 逻辑合理性、按钮功能完备性、返回/导航逻辑、业务闭环与人类直觉

## 总体结论

整体工程质量高——状态机展示、空态文案、破坏性操作确认、判题进度推送都做得认真，**无 P0 级「操作不可达/数据写错」类缺陷**。主要问题集中在：

1. **页面层级上下文丢失**——深链进入二级/三级页后不知道自己在哪个课程/作业；
2. **业务闭环断点**——学生注册无前端入口、ADMIN 账号登录后是死胡同；
3. **错误与空数据被混为一谈**——多处接口失败被静默渲染成「空数据」；
4. **跨页状态/口径不一致**——迟交标记、得分语义、状态映射、返回层级各页各表。

一句话总结：**单页完成度高，页面之间欠连贯**。缺一张全局信息架构图把课程/作业状态与名称贯穿到每个深链页面；补上注册闭环后，学生端即可形成完整心智模型：`登录 → 选课 → 看作业状态 → 做题（带截止与迟交感知）→ 逐点反馈 → 历史可回溯`。

## 一、高优先级问题

### H1. 学生全流程存在「账号来源」断点：登录页无注册入口，注册页不存在 🔴

- 后端已完整提供学生自助注册：`/api/auth/register/code`（邮箱验证码）+ `/api/auth/register`（学号注册即自动激活教师预置名单，`server/.../register/RegisterService.java:76`），前端却**没有任何注册页面或入口**（`App.tsx` 全路由无注册页）。
- 没有账号的学生面对登录页只有用户名/密码 → 死路；教师 Excel 导入的 PENDING 学生正是等待这一步闭环。
- 规格文档写明「学生自助注册前端…后续阶段补」（`docs/superpowers/specs/2026-08-28-计划7-学生端前端-design.md`），属于已知欠账，但它是学生从「被导入」到「能用」的**唯一通道**，建议优先补齐，并在登录页放「没有账号？注册」入口。
- `frontend/src/pages/student/MyCoursesPage.tsx:28` 空态文案「请联系任课教师导入学号后重新登录」只覆盖「已有账号但没被拉进课」的场景，没告诉没账号的学生如何注册。

### H2. ADMIN 账号登录后是「死胡同」，且报误导性错误 🟠

- 无管理员端路由；ADMIN 登录后按「非 STUDENT」被送到 `/teacher/courses`（`frontend/src/pages/LoginPage.tsx:30`），而教师端接口全部 `@PreAuthorize("hasRole('TEACHER')")`，ADMIN 只有 `ROLE_ADMIN`（`server/.../security/JwtAuthFilter.java:50`）→ 页面统一提示「课程列表加载失败 / 题库列表加载失败」（真实原因是 403 无权限，文案误导）。
- 种子账号 `admin/admin123` 登录后什么都点不动。建议：登录页对 ADMIN 提示「管理员功能建设中，请使用教师/学生账号」，或把 ADMIN 引导到只读页。

### H3. 层级上下文丢失：二级/三级页不知道「这是哪个课程/作业」 🔴

- 学生端 `CourseAssignmentsPage` 标题仅「课程作业」、`AssignmentProblemsPage` 仅「作业题目」，通篇无课程名/作业名；深链接进入完全无上下文。
- `frontend/src/pages/student/CodingPage.tsx:46-48` 顶部用**原始 ID** 显示上下文：`课程 12 / 作业 34`——无意义，属调试残留。建议改为名称面包屑（课程名 → 作业名 → 题号）。
- 教师端同病：`CourseStudentsPage`「课程学生名单」、`AssignmentsPage`「作业管理」卡片标题不带课程名（对比 `SubmissionsPage`/`GradebookPage` 标题带「· 作业名」，同一应用两套标准）。
- 建议：统一引入面包屑或「课程名 · 页名」式标题；详情接口补 `courseName/assignmentTitle` 字段（`AssignmentTeacherDetail` 已有 `courseId`，可顺带取名字）。

### H4. 错误与「空数据」被混为一谈，多个页面静默失败 🟠

- `CourseConsolePage` 的 7 个分析查询**无错误处理**：接口 40400（课程不可见/已删）或 5xx 时，页面静默渲染「0 学生 / 暂无提交 / 暂无分数段」——教师会误以为课程真的没数据。同项目其他教师页均有 `useEffect → message.error`，此处是遗漏。
- 学生端 `CodingWorkspace` 提交历史查询失败时，表格显示空态「还没有提交记录，快在右侧写第一段代码吧」——误导（实际是加载失败）；「我的最高分」随之错误显示 `—`。WebSocket 是 best-effort 可接受，但历史列表失败应区分「暂无」与「加载失败」并提供重试。

### H5. 作业状态是「活的」，前端却不把它传进作答流程 🟠

- 学生端只有作业列表页实时展示 `未开始/进行中/宽限中/已截止`，进入题目列表/编码页后**状态信息即断**：
  - 已截止（CLOSED）作业仍可一路点进编码页（题目列表入口只在 NOT_STARTED 置灰，`CourseAssignmentsPage.tsx:31`），直到点「提交评测」才被后端 `作业已截止，无法提交` 弹错——学生写完代码才知白费。
  - 宽限期（LATE_WINDOW）提交会被标记迟交（`server/.../judging/SubmissionService.java:152`），但前端**提交前零提示**。
- 建议：作业列表/题目列表/编码页统一携带 assignment 状态；CLOSED 时禁用提交并说明；LATE_WINDOW 提交前 `Modal.confirm`「已过截止时间，本次提交将标记为迟交」；建议加截止倒计时。

## 二、导航与「返回」逻辑审查

| 页面 | 返回目标 | 评价 |
|---|---|---|
| 学生 `CourseAssignmentsPage` | 「← 我的课程」→ `/student/courses` | ✅ 合理 |
| 学生 `AssignmentProblemsPage` | 「← 作业列表」→ 课程作业列表 | ✅ 合理 |
| 学生 `CodingPage` | 「← 题目列表」→ 作业题目列表 | ✅ 合理，链式返回正确 |
| 学生 `PracticeCodingPage` | 「← 返回题库」 | ✅ |
| 教师 `CourseConsolePage` | 「← 全部课程」 | ⚠️ 从列表进入时正确；但从「学生名单/作业管理」返回时无法回到工作台 |
| 教师 `CourseStudentsPage` | 「返回」→ `/teacher/courses`（课程列表） | 🔴 **层级跳跃**：从「工作台」进入，返回却跳过工作台到列表顶层 |
| 教师 `AssignmentsPage`（课程作业管理） | **无任何返回/面包屑** | 🔴 全站唯一无法导航回上一级的管理页 |
| 教师 `AssignmentDetailPage` | 标题内「返回作业列表 + 课程工作台」两个链接 | ✅ 内容合理；样式与全站返回按钮不一致，可发现性差 |
| 教师 `ProblemDetailPage` | 硬编码 `→ /teacher/problems` | ⚠️ 从 `AssignmentDetailPage` 点题目名进入时返回题库顶层——**丢失来路** |
| 教师 `PlagiarismPage` | 「← 返回作业」 | ✅（从工作台查重汇总进入时略绕，可接受） |
| 教师 `GradebookPage`/`SubmissionsPage` | 「返回作业详情」 | ✅ 与上一级一致 |

**关键发现**：

1. **三级层级（课程列表 → 课程工作台 → 学生/作业/题目）返回链不完整**：学生端逐级返回做对了，教师端普遍「一步跳回顶层」。建议教师端统一面包屑：`全部课程 / 课程工作台 / 当前页`。
2. **返回按钮样式五套并存**：`Card title` 内小号 text 按钮（Students/Detail）、正文普通 Button（Console/Plagiarism）、text 按钮 + `<span>←</span>` 图标（学生端）、无返回（AssignmentsPage）。建议收敛为受控组件。
3. 返回全部用**固定路由**而非 `history.back()`，对深链接友好，方向正确；问题只在「跳到哪一层」不一致。

## 三、按钮/功能完备性审查（逐页）

### 3.1 登录页 `LoginPage`

- ✅ 必填校验、回车提交、错误 toast、按角色分流均正确。
- ❌ 缺「注册」「忘记密码」入口。后端**无密码找回接口**，学生忘记密码只能靠管理员，而管理员端不存在——闭环断点（见 H1/H2）。
- 🟡 退出登录是 `<a>` + icon（无 href、无键盘语义），建议 antd Button text；登出无二次确认可接受。

### 3.2 学生「我的课程」`MyCoursesPage`

- ✅ 卡片式、hoverable、空态带 CTA「去自由练习」，体验最好的一页。
- 🟡 卡片只有课程名 + 学期，无任课教师、作业数、最新动态；无搜索（规模 <200 可暂缓）。

### 3.3 学生课程作业 / 题目列表

- ✅ 未开始置灰、分页、截止说明文案齐。
- 🟡 缺每题/每作业完成状态列（哪些 AC 了），学生靠记忆或逐个点进；题目列表无排序/分组。
- 🟡 分页 `page` state 在课程切换时不重置（组件复用），第 2+ 页的小课程会出现「空表 + 页码超出」困惑态；教师端 `AssignmentsPage`/`CourseStudentsPage`/`SubmissionsPage` 跨课程/作业切换同理，应重置页码与筛选。

### 3.4 编码工作区 `CodingWorkspace`（核心页）

- ✅ 双栏布局、实时判题进度、提交 loading 防抖、行点击看详情、样例/隐藏点严格分流、代码深色主题，专业 OJ 水准。
- 🔴 **「我的最高分」语义混乱**（`CodingWorkspace.tsx:99-102, 194-196`）：
  - 练习模式得分恒 `null`（后端约定），标签永远灰色 `—`，哪怕刚 AC；提交记录「得分」列也恒 `—`——练习用户得不到「我过了」的正反馈。
  - 作业模式只要提交过，`bestScore` 就是数字（含 **0**），标签显示「我的最高分：0」仍为**绿色**（`bestScore == null ? default : green`），误导性强。
  - 建议：练习模式隐藏得分标签，改显「已通过 N 次」；作业模式按 `=== 满分 / 0 / 部分` 分色，或仅满分亮绿。
- 🟠 **样例 WA 无「你的输出」**：学生详情抽屉里 WA 样例点只有「输入 + 预期输出 + message」，无自己程序的实际输出（`server/.../judging/StudentSubmissionViews.java` 无此字段，需后端补 `actualOutput`）——学生无法定位差异，是编码平台最影响体验的点之一。
- 🟠 **切语言不换代码**（`onLanguageChange` 仅空代码时注入模板）：写完 C 切 Java 直接提交 → 必 CE；建议按语言分存草稿或切换时明确提示。
- 🟡 历史表格有 `isLate` 字段但列表不展示（详情抽屉才有「迟交：是/否」），与教师端列表「迟交」Tag 不一致；配合 H5 应在此醒目提示。
- 🟡 WS 断线无重连（`ws.ts` `reconnectDelay: 0`）可接受，但断线后实时进度条永停最后状态且页面无「连接断开」提示；`FINISHED` 只刷历史列表不刷已打开的详情抽屉缓存（30s 内重开可见旧状态）。
- 🟡 模板原样代码也可提交，建议空/模板代码提交前确认或禁用。
- 🟡 401 整页跳登录会**清空编辑器未提交代码**，无挽留；建议至少本地存草稿。

- ✅ 分页题号跨页计算正确。
- 🟡 无难度/通过率/我的状态列，练习进展不可见。

### 3.12 成绩册 `GradebookPage`

- 🟡 行点击进对比抽屉有 cursor 但无 hover 提示文案（可用）。

## 四、跨页一致性与「人类直觉」问题汇总

1. **标题体系三套并存**：学生端 `h2 + sub` 统一；教师端 `Card title`（Courses/Students/Assignments/Detail/Submissions/Gradebook）与 `h2 + sub`（Console/Plagiarism）混用——同一角色两种骨架。
2. **状态文案/颜色映射重复定义**：教师端 `STATUS_META` 在 `AssignmentsPage`、`AssignmentDetailPage`、`SubmissionsPage` 各抄一份且颜色口径不一（如 RE 的 error vs 学生端 volcano）；学生端已收敛至 `constants.ts`。教师端应同样抽公共模块，避免漂移。
3. **迟交标记不一致**：教师列表可见、学生列表不可见（详情都有）。
4. **多处「接口失败」当「空数据」展示**：学生我的课程、编码区历史、教师工作台图表（见 H4）。
5. **「得分」口径困惑**：练习恒 `—`、作业 0 或满分，学生端无一句话解释「练习不计分、作业全对才得分」——建议在练习页与工作区加说明，或练习模式不渲染得分列。
6. **隐藏测试点数量对学生的可见性**：学生提交详情会枚举「第 N 个隐藏测试点」并展示「通过 X/Y 点」——若 CLAUDE.md「零泄漏红线（输入/输出/数量）」按字面约束，此处**已泄露隐藏点数量**；若口径为「仅输入输出不可见」需在文档澄清。建议与后端对齐口径并注明界面。
7. **做得好的细节**：菜单高亮、sticky 顶栏、双栏布局 960px 断点降级单列、编辑器 `sticky top: 72` 常驻视口。
